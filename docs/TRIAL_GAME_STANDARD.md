### 0.4 이 초석으로 바뀌거나 분명해진 점

- 플레이어는 이름을 가진 재판장이다. 호명·입정·기립·착석·직접 개정과 상대 반응이 있다(ID-01~05).
- 기본 법정은 높은 판사석 1인칭, 보는 사람 기준 **검사 오른쪽·변호인 왼쪽**, 판사석 전경(손·문서·마이크)(VS-01~03). 이미 정한 배치·수동 진행을 다시 미정으로 돌리지 않는다.
- 이야기 축은 관찰 → 질문 → 근거 제시 → 해명·번복 → 후속 검증 → 판단이다. 정답만 맞히고 넘어가는 구조로 줄이지 않는다(EV-04~06).
- 질문은 장면·인물·쟁점별로 쓴다. **모든 인물에 공통 질문 2개와 비슷한 답을 붙인 것은 1편 동등 구현이 아니다**(QA-01). 자유 입력이 준비 응답이면 그렇게 안내한다(QA-08).
- 유죄·무죄를 플레이어가 고른다(JD-01). 진상은 고정이고 판결에 따라 결과만 바뀐다(JD-07). 정상 UI로 갈 수 없는 결말은 개수에 넣지 않는다(JD-09). 판결 이유 길이 검사를 논리·법률 채점이라고 부르지 않는다.
- 선고 뒤 겉반응·속마음·시간 경과 후 삶을 보여 준다(JD-05·06).
- 의사봉은 시리즈 필수 연출이 아니다. 과거 문서는 피하라고 했고 운영판에는 장식으로만 남아 있다(원문 §2.2).
- 새 사건은 사건 ID·URL·자산 경로·저장 키·회원 게임 ID를 분리한다. 1·2편을 덮어쓰지 않는다.
- 새 사건 제작 순서(원문 §8): 요구 수용표 → 고정 진상표 → 증거표 → 서사·퍼즐 → 대화표 → 화면·자산표 → 엔딩 도달표 → 구현 → 3회차 검수(핵심 플레이·실패 복구·회귀·운영) → 인수인계. 검수표 67항목을 적용/변경/미구현/확인 필요로 분류하고 조용히 지운 기능이 없게 한다.
- 판정은 PASS / FAIL / NOT TESTED / BLOCKED. 의도된 제외(SKIP·해당 없음)는 근거를 함께 적는다. 이전 결과 수치를 새 결과로 옮기지 않는다.
- 화면 확인 범위: 320·390·430·768px, 가로모드, 1366×768, 1920×1080. 브라우저 창 크기 변경·DOM 검사는 실기기 검수가 아니다.
- 원문에 따르면 사건 002는 사이트 v189로 운영 배포됐다(`docs/TRIAL_CASE002_HANDOFF.md`의 “미배포”는 작성 시점 정보). 이 저장소에서는 운영 상태를 확인하지 못했다.
- 원문을 읽었다는 것만으로 배포 권한이 생기지 않는다. 배포는 그때 사용자가 요청한 범위를 따른다.

## 1. 작업 순서

1. HTML과 인수인계를 **현재 기준**으로 읽는다. 기존 대화나 이전 시험본보다 우선한다.
2. 변경 **전에** 계획을 사용자에게 보고한다.
3. 기존 화면·서사·증거·고정 진상을 유지하며 고친다.
4. 변경 **후에** QA 결과를 보고한다. 검증한 것과 검증하지 않은 것을 나눈다.
5. 사용자 승인 전에는 배포하지 않는다. 사용자가 배포 전 직접 확인하겠다고 했다.

## 2. 임의로 없애면 안 되는 것

- 판사 이름 입력, 법정 입장 화면, 판사석 시점 배경, 검사·변호인의 “존경하는 ○○ 재판장님” 호명
- 자동 시간 진행 없음. 사용자가 눌러야 다음 장면으로 간다.
- 재판장의 선택형·직접 질문과 답변, 그 초안·쟁점·취지 선택 저장. 자유 입력은 선택한 쟁점에 맞는 **준비된 응답**으로 이어진다(LLM 대화나 법률 의미 판정 아님).
- 이전 장면·다음 기록·현재 공판 복귀. 지난 장면 열람은 진행을 되돌리지 않고, 지난 선택을 수정하거나 미래 증거를 열지 않는다.
- 선고 뒤 「법정 밖, 남겨진 마음」 3장면(피고인·증인·유가족), 유무죄·조사 범위에 따른 변화
- 4개 장, 본 공판 30장면, 핵심 대조 3개, 선택 재신문, 증거 순차 접수
- 저장 호환(아래 4장)
- 시각 연출: 3×2 초상 시트의 화자별 표시(대사 중 큰 초상, 발언자 작은 초상, 직접 질문 응답 초상, 선고 반응·후일담 초상), 진영 색, 카메라, 타자 효과, 장 제목 카드, 모순·명령·선고 연출, 상단 대조 표시, 판결 인장

**회원 적립·칭호·커뮤니티 연동은 독립 HTML에서 의도적으로 분리돼 있다.** 삭제된 기능으로 오해하지 않는다. `<html data-release-mode="review">`에서는 회원 슬롯을 그리지 않고, `site`에서만 그린다.

## 3. 만들 때 지킬 형식

- 독립 HTML은 이미지·스타일이 내장된 단일 파일이다. **외부 이미지·스타일·스크립트(웹폰트 포함)를 불러오지 않는다.** 외부를 가리키는 것은 안내 화면의 법률 출처 링크뿐이다.
- 이 독립 HTML을 사이트 소스에 그대로 덮어쓰지 않는다. 실제 사이트를 고치려면 인수인계 9장의 Sites 소스 경로와 회원 서버 구현을 먼저 받아서 읽고 같은 구현에 적용한다. 이 저장소(webgame-lab)에는 그 소스가 없다.
- 초상 시트·배경은 WebP로 넣는다. 큰 data URI를 CSS 변수에 넣지 않는다. 2.9MB PNG를 CSS 변수에 넣었을 때 Chromium이 변수를 비워 모든 초상이 빈칸이 된 사례가 있다.
- 렌더마다 큰 base64 문자열을 `innerHTML`에 다시 넣지 않는다. 시작할 때 Blob URL로 한 번 바꾼다.
- 모션 줄이기에서 타자 효과·장 카드·카메라 이동·흔들림을 끄고, 숨겨진 글자가 남지 않게 한다.

## 4. 저장 호환을 설명하는 정확한 표현

| 구분 | 현재 키 | 이전 키 |
| --- | --- | --- |
| 사이트용 | `ttanjitmoa-court-002-v2` | `ttanjitmoa-court-002-v1` |

- **v2 → v2.4:** `caseId '002'`, `schema 2` 저장을 검증 후 복원하고, 새 필드는 기본값으로 채운다. 주문·유무죄·형량이 모순된 완료 기록은 완료로 인정하지 않고 판결문 초안 단계로 되돌린다. 핵심 공판 기록은 따로 보존하지만 선택형 추가 발언에는 최근 기록 한도가 있다.
- **v1 → v2.4:** v2 저장이 없을 때만 v1을 확인한다. v1 원본은 지우지 않고 이름·메모·판결문 초안을 가져온다. 현장 검증 진입점 `scene: 6`부터 다시 심리하며 초기 자료 3개를 열고 이전 해결·조사·완료 판정을 초기화한다. 시작 화면에 ‘개정된 증거부터 이어하기’와 안내가 나온다.
- 따라서 **“모든 구버전에서 정확히 중단한 화면을 그대로 이어간다”고 말하지 않는다.**
- 사이트용과 검수용 저장은 서로 다른 영역이다. 자동 이전되지 않는다. 새 파일명·새 위치로 연 HTML은 예전 저장을 못 읽을 수 있다. 클라우드 동기화, 저장 JSON 내보내기·가져오기는 구현 범위가 아니다. 판결문 다운로드는 진행 백업이 아니다.

## 5. 회원·칭호·커뮤니티 계약 (사이트용)

- 비회원도 플레이한다. 적립은 유효한 회원 플레이 티켓으로 선고까지 완료한 경우에만 한다.
- 사건 001과 002는 서로 다른 클리어다. 같은 사건 재플레이·완료 요청 재전송은 중복 집계하지 않는다.
- 유무죄·정답 여부와 무관하게 재판 완료를 기준으로 한다.
- 끝난 비회원 저장을 로그인 뒤 열기만 해서는 소급 적립하지 않는다.
- 클라이언트가 보낸 칭호 ID·누적 숫자를 믿고 승급시키지 않는다.
- 기본 표시는 획득한 최고 칭호를 자동 선택하되, 사용자가 이전 칭호나 숨김을 직접 고르면 존중한다.

- 기존 회원의 완료 기록·수동 선택 칭호를 유지하고, 정지·탈퇴 시 배지 처리도 기존대로 둔다.

- 현장 인원은 피해자 이준서, 피고인 강태오, 증인 문시현, 총 3명이다. 제4자는 없다.
- 고정 진상: 강태오가 공격했고 문시현은 문을 막았다. 증인의 별도 형사책임까지 이 사건 피고인에 대한 선고로 확정하지 않는다. 진상은 플레이어의 선고로 바뀌지 않는다.
- 피해자는 사망했다. 좋은 판단의 후일담은 유가족의 일상 회복으로 표현하고, 피해자가 살아 돌아오는 장면을 넣지 않는다.
- 피고인의 무죄 뒤 숨긴 미소, 증인의 후회, 유가족의 세 달 뒤는 속마음·행동 묘사로 대사와 구분한다. 속마음은 선고 뒤 창작상 공개 정보이며 공판의 증거가 아니다.
- 1심 선고를 곧 확정판결로 쓰지 않는다.
- 초상은 검사·변호인·피고인·증인·감정인·유가족 6명의 3×2 정적 이미지다. 표정 변화·감정 애니메이션은 구현돼 있지 않으므로 있다고 말하지 않는다.
- 배경은 판사석 시점이다. 검사 좌우 배치의 현실 법정 일반화는 검증 범위가 아니다.

## 7. 회귀 체크리스트 (v2.4 QA 수정 11항목)

고칠 때마다 이 항목이 다시 깨지지 않았는지 확인한다.

- [ ] 직접 질문 응답창에 해당 발언자 초상이 나온다.
- [ ] 제삼자 행동 설명이 인물 대사에 섞이지 않는다(대사와 상황 설명 분리).
- [ ] CCTV 프레임을 인용해도 화면이 첫 프레임으로 돌아가지 않는다.
- [ ] 직접 질문·답변의 쟁점·취지 선택이 저장·복원된다.
- [ ] 선택 발언이 많아져도 초기 공판·핵심 증거 기록이 남는다. 없는 과거 기록을 현재 대사로 대체하지 않는다.
- [ ] 도움말·모달을 닫아도 진행 중 증거 대조 화면이 사라지지 않는다.
- [ ] 미확보 증거의 정답 암시가 심증 보드에 먼저 나오지 않는다.
- [ ] 증인·피해자를 선고 대상으로 적은 주문은 막힌다.
- [ ] 현장 인원 표현에 제4자가 없다는 점이 분명하다.
- [ ] 좁은 화면에서도 도움말 버튼이 보인다.
- [ ] 모달 안에서 키보드 초점이 순환하고, 닫으면 호출 버튼으로 돌아간다.

## 8. 보고 규칙

- 검증하지 않은 브라우저·기기·계정 경로를 PASS로 보고하지 않는다. 결과는 PASS / FAIL / SKIP(의도된 제외) / NOT TESTED로 적는다.
- 헤드리스 Chromium 자동 플레이, DOM 검사, 서버 검사는 **실제 브라우저·실기기 검수와 같은 것으로 취급하지 않는다.** 무엇으로 확인했는지 적는다.
- 실기기 QA 전에는 ‘최종 검수 완료’라고 쓰지 않는다.
- 구현, 자동 검증, 병합, Preview, 공식 도메인 반영을 각각 다른 상태로 적는다.
- `case002-qa-preapproval-site.tar.gz`는 무결성 검사에서 EOF 오류가 났다. 전달본이나 배포 입력으로 재사용하지 않는다. 배포 지시를 받으면 정상 소스에서 다시 만들고 무결성을 확인한다.
