# 딴짓모아 추리재판 — 시리즈 제작 인수인계

문서 버전: 1.0 · 작성일: 2026-10-18 · 대상: 다른 ChatGPT 대화, Claude, 후속 개발자

**목적: 「11분의 공백」에서 만들었던 재판장 체험을 다음 사건에서도 빠짐없이 이어 간다. 사건 이름과 줄거리만 바꾼 추리 퀴즈나 일반 기록 열람 게임으로 축소하지 않는다.**

이 문서는 과거 맥락에서 확인한 요구, 실제 배포 소스의 동작, 후속 제작에 적용할 기본값을 구분한다. 사용자 계정의 모든 과거 대화를 전수 열람했다는 뜻은 아니다. 확인 가능한 대화 맥락·기존 인수인계·파일과 실제 배포 버전 소스를 대조했다. “1편과 똑같이”라는 말만으로 누락이 반복되지 않도록 구체적인 행동과 검수 기준으로 적었다.

## 1. 다음 AI가 먼저 읽을 핵심

1. 플레이어는 **재판장**이다. 이름을 입력하고, 호명되어 입정하고, 판사석에 앉고, 직접 공판을 연다. 다른 인물은 플레이어의 발언에 반응한다.
2. 기본 카메라는 **높은 판사석에서 내려다보는 1인칭**이다. 판사석·서류·마이크·손이 전경에 있고, **화면을 보는 사람 기준 검사 오른쪽 / 변호인 왼쪽**이다. 실제 법정 일반론으로 이 배치를 바꾸지 않는다.
3. 발언·증거·모순 지적·진술 번복·판결·후일담을 수동으로 진행한다. 자동 넘김, 제한시간, 강제 카운트다운을 넣지 않는다.
4. 이야기의 핵심은 **관찰 → 질문 → 근거 제시 → 상대의 반응·진술 변화 → 다시 확인 → 판단**이다. 문제 정답만 맞히고 다음 카드로 넘어가는 구조로 축소하지 않는다.
5. 사건의 실제 진상은 제작 전에 고정한다. 유죄·무죄 선택에 맞추어 범인이나 과거 사실을 바꾸지 않는다. 플레이어가 확인한 증거와 작가만 아는 진상을 따로 관리한다.
6. 질문 기능은 사건과 장면에 맞게 쓴다. 모든 인물에게 공통 질문 두 개와 비슷한 답만 붙인 상태를 1편 동등 구현으로 판정하지 않는다.
7. 직접 입력한 판사 발언과 판단 이유를 보존한다. 실제 의미 이해를 구현하지 않았다면 AI가 자유 질문을 이해한다거나 판결문을 법적으로 채점한다고 말하지 않는다.
8. 판결 뒤 인물의 겉반응, 속마음, 시간 경과 후 삶을 보여 준다. 결과 도장이나 한 줄 정답 해설로 끝내지 않는다.
9. 저장·불러오기·기록 재열람·메모·판결문 내보내기·다시하기·전체화면·회원 완료/칭호 연동을 공통 기능으로 취급한다. 시나리오를 새로 쓴다는 이유로 지우지 않는다.
10. 새 사건은 별도의 사건 ID·URL·자산 경로·저장 키·회원 게임 ID를 사용한다. 1편과 2편을 덮어쓰지 않는다.
11. 기획 문장이나 버튼의 존재만으로 “반영 완료”라고 하지 않는다. 실제 화면·상태 변화·저장 복구·도달 가능한 분기로 증명한다.
12. 모르는 사항은 질문한다. 다만 이미 확정된 시점·좌우 배치·수동 진행 등을 새 대화에서 다시 미정으로 돌리지 않는다.

## 3. 확정 요구와 아직 확인이 필요한 정책

표의 “기본값”은 답변이 없을 때 1편을 재현하기 위한 작업 기준이다. 새로운 사용자 확답으로 기록하지 않는다.

| 구분 | 내용 | 처리 |
|---|---|---|
| 확정 | 재판장 역할·이름·입정·착석·개정, 높은 판사석 시점, 검사 오른쪽/변호인 왼쪽 | 후속 사건에도 유지 |
| 확정 | 수동 진행, 무제한 생각할 시간, 불필요한 필수 입력 최소화 | 후속 사건에도 유지 |
| 확정 | 고정 진상, 구체적 증거, 질문에 대한 상대 반응, 진술 변화, 판결 이유, 후일담 | 후속 사건에도 유지 |
| 기본값 / 인터뷰 미답변 Q1 | 핵심 퍼즐을 모두 해결해야 선고할 수 있음 | 현재 1편 방식 적용. 미완성 조사 선고를 새 표준으로 도입하지 않음 |
| 기본값 / 인터뷰 미답변 Q2 | 선고는 유죄·무죄 선택과 판단 이유 작성 | 현재 1편 방식 적용. 형량·양형 이유를 새 시리즈 필수로 확정하지 않음 |
| 사건별 변경 가능 | 인물·범행·공간·증거·모순·장 수·발언 수·퍼즐 수 | 기능적 깊이를 유지하며 설계 |
| 제안, 아직 미승인 | 클릭 수 감소, 질문의 실제 자연어 이해, 문장 내용 평가, 미완성 조사 분기 | 별도 개선 범위로 제안. 기존 기능이라고 주장하지 않음 |

인터뷰 질문은 “Q1: 핵심 추리 해결 후에만 선고 / 미해결 상태도 선고”, “Q2: 유무죄와 이유 / 형량까지 포함”이다. 이번 문서 작성 중 선택값이 전달되지 않았다. 답변을 받으면 해당 행과 검수 기준을 함께 수정한다.

## 4. 시리즈 공통 제작 규격

이 절은 후속 사건 제작 시 사용하는 기능 계약이다. 1편의 수치 자체를 모두 강제하지 않고, 각 기능이 주는 경험을 유지한다. 각 행은 후속 제작의 확인 기준이며, 모든 행이 과거 1편에서 완벽하게 검증됐다는 선언은 아니다. 현재 구현의 사실·한계는 §5와 §9.3을 함께 읽는다. 개선 제안은 별도로 표시한다.

### 4.1 재판장이 되는 시작

| ID | 유지할 동작 | 확인 방법 |
|---|---|---|
| ID-01 | 시작 전에 재판장 이름을 입력받고 이후 호칭·판결문에 일관되게 사용 | 한글 이름 입력 후 입정·질문·판결문까지 확인 |
| ID-02 | 입정 알림, 기립 반응, 판사석 착석, 직접 개정 선언의 흐름 | 새 게임에서 각 장면·조작 확인 |
| ID-03 | “존경하는 ○○ 재판장님” 등 플레이어를 향한 호칭 | 대사가 고정 이름이나 다른 사건 판사 이름을 쓰지 않는지 확인 |
| ID-04 | 재판장이 지시하면 인물이 그 지시에 응답하고 절차가 진행 | 명령 후 상대 대사·기록 변화를 확인 |
| ID-05 | 마지막 선택 화면 외에도 재판장이 공판을 이끈다는 체감 | 초반·증거조사·진술 번복·최후진술에서 판사 행동 확인 |

1편은 이름 최대 16자, 2편은 최대 24자이며 기본 이름 처리도 다르다. 새 사건에서 길이를 달리 정할 수 있지만 입력값 유실·깨짐을 허용하지 않는다. 이름이 바뀌면 모든 동적 호칭을 일관되게 갱신한다.

### 4.2 화면과 연출

| ID | 유지할 규격 | 구현·검수 포인트 |
|---|---|---|
| VS-01 | 기본 법정 화면은 높은 판사석에서 보는 1인칭 | 일반 관객석 시점·법정 옆면 시점으로 기본 구도를 교체하지 않음 |
| VS-02 | 검사: 보는 사람의 오른쪽 / 변호인: 왼쪽 | 메인 그림·확대 화면·모바일 자르기·이름표 모두 교차 확인 |
| VS-03 | 판사석 전경에 손·문서·마이크 등 역할을 체감할 요소 | 인물 얼굴 카드와 기록 패널만으로 기본 화면을 대체하지 않음 |
| VS-04 | 발언자·역할·대사·지문을 구분 | 제3자의 행동 묘사를 해당 인물이 말한 대사처럼 처리하지 않음 |
| VS-05 | 증거 제시·모순 발견·진술 번복·선고의 장면 변화 | 배경 한 장을 모든 순간에 반복하는 것으로 동등 구현이라 하지 않음 |
| VS-06 | 후일담은 사건 결과에 맞는 인물 모습과 상황 | 사망한 피해자가 살아 돌아오는 등 상태 모순 금지 |
| VS-07 | 타이핑·장면 전환·도장·카메라 이동은 장식이며 진행권은 사용자에게 있음 | 애니메이션이 다음 발언·선고를 자동 확정하지 않음 |
| VS-08 | 동작 줄이기·글자 크기·키보드 조작을 고려 | 설정 후에도 핵심 정보·조작이 사라지지 않음 |

“항상 모든 컷이 1인칭”이라고 현재 1편을 설명하면 부정확하다. 기본 법정 구도는 판사석 1인칭이지만 증언·대치 컷에는 어깨 너머나 확대 장면이 있다. 이런 보조 컷은 허용하되, 기본 정체성과 좌우 배치를 잃지 않는다.

1편의 여성 검사·남성 변호인, 색상과 복장을 모든 새 사건의 고정 인물 설정으로 강제하지 않는다. **인물은 새로 만들 수 있고 공간 배치와 역할은 유지한다.** 장식용 참조 그림까지 모두 실제 사용 장면 수로 세지 않는다.

### 4.3 진행과 추리

| ID | 유지할 규격 | 구현·검수 포인트 |
|---|---|---|
| FL-01 | 사용자가 누를 때만 다음 발언·프레임·후일담 진행 | 대기만으로 장면 번호가 바뀌지 않음 |
| FL-02 | 제한시간·실패 카운트 압박 없음 | 시간 초과 패배·숨은 타이머 도입 금지 |
| FL-03 | 주요 단계와 현재 쟁점을 알 수 있음 | 장·핵심 증거 진행 표시와 다음 행동 안내 |
| FL-04 | 지나간 기록은 재열람 가능, 미래 기록은 잠금 | 기록 보기로 미래 정답·자백·후일담이 새지 않음 |
| FL-05 | 재열람은 현재 진행 상태를 훼손하지 않음 | 과거 화면 종료 후 현재 위치·초안·선택 유지 |

### 5.5 네 퍼즐의 정답과 인과관계

| 퍼즐 | 플레이어가 하는 일 | 정답 | 오답·다른 선택의 의미 |
|---|---|---|---|
| 차량 탐색 | 위치·촬영 방향·도착 시각을 보고 영상 차량 선택 | B3-17 흰 승합차 | B3-05 기둥 가림 / B3-12 벽 방향 / B3-21 22:40 도착 |
| 증거 비교 | 진술 문구 + 프레임 + 비교 기준 조합 | “이미 쓰러져” + 두 번째 프레임(`frame1`) + 자세 | 차·조명 등은 해당 거짓 설명을 직접 검증하지 않음 |
| 시각 보정 | 독립 기록 두 개로 영상 시계 검증 | 표시 시각에서 90초 빼기(`-90`) | `0`, `+90`은 두 기준점에 맞지 않음 |
| 결정적 장면 제시 | 마지막 해명과 충돌하는 장면 지적 | 세 번째 프레임(`frame2`), 팔을 휘둘러 가격 | 서 있는 장면이나 몸을 숙여 돕는 장면은 직접 가격 장면과 다름 |

시각 보정의 교차 확인: 영상 22:17:38 → 출입 기록 22:16:08, 영상 22:23:30 → 신고 22:22:00. 따라서 영상 22:20:10 → 실제 22:18:40이다. 영상 UI는 5개의 정지 프레임으로 구성되어 있으며 실제 동영상 파일 재생이 아니다.

### 5.6 질문·재판장 응답

18개 질문 ID: `identity`, `charge`, `position`, `arrival`, `memory`, `injury`, `money`, `message`, `time`, `blood`, `view`, `error`, `original`, `clock`, `contradiction`, `confession`, `payment`, `family`.

대상: 검사·변호인·피고인·피해자·목격자·설비 담당·감정인·피해자 누나·피고인 어머니.

필수 판사 발언 장면 ID: `o-charge`, `o-defense`, `h-victim`, `h-deposit`, `f-deflect`, `l-last`.

원본 제출 취지의 지시는 뒤 검사 발언에, 배려 취지의 응답은 유죄 후일담 일부에 반영된다. 그 외 다수 선택은 대사·기록을 풍부하게 하며 본편의 큰 경로를 바꾸지 않는다. 따라서 “모든 말이 이후 이야기를 바꾼다”고 표현하면 과장이다.

### 5.7 판결과 실제 도달 가능한 엔딩

### 7.2 저장과 호환

1편 메인 키는 `ttanjitmoa-court-001-v2`, 관련 키는 `-notes`, `-prefs`, `-navigation`이다. 이전 `ttanjitmoa-court-001-v1` 저장은 보존하며 해당 진행이 있으면 옛 버전으로 연결하는 흐름이 있다. 로컬 브라우저 저장이며 기기 간 자동 동기화가 아니다.

새 사건 예: 사건 003이라면 별도 slug와 `ttanjitmoa-court-003-…` 계열을 정한다. 이 예시 자체가 최종 사건 ID 승인이라는 뜻은 아니다. 기존 할당을 먼저 확인한다.

구버전 데이터를 전부 새 데이터와 동일하다고 간주하지 않는다. 필드별로 “그대로 복원 / 변환 / 안전한 지점으로 이동 / 사용자에게 안내”를 설계한다. 기존 유효한 판결문·메모·직접 입력을 이유 없이 지우지 않는다. 판결문 TXT는 전체 진행 백업 파일이 아니다.

2편 참고: v2 계열은 schema 2를 사용한다. v1은 이름·메모·판결 초안을 가져오되 특정 심리 지점부터 다시 시작하는 방식이라 정확한 장면 이어하기와 다르다. 이 정책을 1편이나 새 사건에 검토 없이 복사하지 않는다.

### 7.3 전체화면과 운영 연결

외곽 페이지의 `window.TTMTrialFullscreen` 및 게임 측 화면 인터페이스와 연결한다. 1편에는 `window.TTMTrialScreen`이 있다. 부모 iframe을 재생성하거나 URL을 다시 로드하는 방식으로 전체화면을 구현하면 진행이 초기화될 수 있으므로 피한다. 브라우저 지원이 없을 때도 플레이 가능한 화면을 제공한다.

회원 공통 모듈의 `createTrialRewards`·`mountTrialRewards` 계열을 참고한다. 주요 서버 경로는 `/api/member/status`, `/api/member/start`(게임 식별), `/api/member/complete`(실행 식별), `/api/member/title`이다. 정확한 요청·응답 필드는 현재 서버 소스를 확인한 뒤 구현한다. 경로 이름만 보고 새 임의 서버를 만들지 않는다.

`memberRunKey`는 실행별 식별자로 유지되며 다시하기에는 새 값이 필요하다. 서버 시작 티켓·계정 소유권·중복 완료·네트워크 재시도·중간 로그아웃/계정 전환을 확인한다. 완료 요청은 사건 완료와 회원 정책을 위한 것이며 판사 이름·자유 질문·판결 이유의 서버 동기화 기능이 아니다.

### 7.4 현재 칭호 정책

| 자격 | 기본 단계 |
|---|---|
| 0개 | 초임판사 |
| 서로 다른 사건 10개 | 판사 |
| 20개 | 부장판사 |
| 30개 | 수석부장판사 |
| 40개 | 지방법원장 |

별도 `first-verdict` 칭호는 “첫 선고”다. 확인 당시 공개 사건은 2개라 10개 이상 단계는 정상 공개 플레이로 아직 달성할 수 없다. 이 정책을 임의로 1·2·3개 기준으로 조정하지 않는다. 실제 적용은 서버가 최종 권한을 가진다.

### 7.5 운영판과 검토판

운영판은 사이트 자산·회원·외곽 전체화면 등에 의존한다. HTML 하나만 파일로 열어 전체 동작이 되리라고 가정하지 않는다. 검토용 단독 HTML을 제공한다면 이미지·스타일·필수 스크립트를 포함하고 운영 회원 API는 검토 환경에 맞게 분리한다. 저장 키도 검토판과 운영판을 분리하고 서로 자동 동기화된다고 설명하지 않는다.

2편의 기존 독립 검토판은 `-review` 저장 키를 썼다. 이 파일을 운영 `index.html`에 덮어쓰면 안 된다. 옛 전달용 tar.gz에는 손상 기록이 있으므로 출처·해시·압축 해제를 확인하지 않은 옛 묶음을 기준으로 쓰지 않는다.

## 8. 다음 사건 제작의 실제 순서와 산출물

1. **요구 수용표**: 이 문서 ID별로 적용 / 사건 특성상 변경 / 미구현 / 확인 필요를 적고, 변경 이유를 붙인다. 기능 이름만 복사하지 않는다.

4. **서사와 퍼즐**: 발견 경로, 조작, 정답, 대표 오답별 피드백, 힌트, 상대 반응, 새로운 기록, 다음 장면을 연결한다.
5. **대화표**: 장면별 발언자·호칭·판사 행동·상대 답·상태 변화·필수 여부·저장 필드를 작성한다.
6. **화면·자산표**: 입정·기본 법정·증언·증거·대치·번복·판결·후일담에 필요한 화면과 컷을 배치한다. 좌우 구도를 먼저 검수한다.
7. **엔딩 도달표**: 유무죄와 조사 범위에 따라 실제 가능한 경로를 적는다. Q1 기본값을 쓸 때 미완성 조사의 가짜 엔딩 수를 늘리지 않는다.
8. **구현**: 공통 기능·사건별 콘텐츠를 구분하여 작업하고, 작동하는 게임과 소스를 함께 만든다. 기존 사건을 보존한다.
9. **검수와 수정**: 핵심 플레이·실패 복구·운영 회귀 세 회차를 기록한다. 못 한 검사는 NOT TESTED로 남긴다.
10. **다음 인수인계**: 정확한 파일·커밋·해시·수정 목록·한계·미답변 정책·실행 방법을 전달한다. 배포 여부는 실제 기록을 확인해 적는다.

필요한 산출물은 사건 설정표, 전체 대사·질문·반응, 증거·퍼즐 설계, 실제 게임, 자산, 테스트 결과, 변경점·인수인계다. 현 작업은 인수인계 문서 작성이며 게임 수정이나 재배포를 포함하지 않는다. 후속 AI도 단순히 이 문서를 읽었다는 이유로 배포 권한이 생겼다고 해석하지 말고 그때의 사용자 요청 범위를 따른다.

## 9. 완료 판정과 검증의 범위

### 9.1 최소 확인 경로

- 새 게임 → 이름 → 입정 → 착석 → 개정 → 양측 입장 → 증거 확보 → 각 퍼즐 정답/대표 오답 → 진술 변화 → 최종 의견 → 판결 작성 → 선고 → 반응 → 후일담 → 판결문 다운로드 → 다시하기 → 두 번째 플레이.
- 질문 직접 작성, 준비 질문 선택, 상대 응답, 로그 확인, 초안 복원.
- 증거·과거 대사 재열람 후 현재 장면 복귀. 미방문 기록·미래 결말 접근 차단.
- 조사·판결 초안·선고 뒤 각각 새로고침. 손상 저장·구버전·저장 불가 환경.
- 전체화면 진입/종료, 빠른 중복 입력, 동작 줄이기, 글자 크기, 모달 키보드.
- 게스트 완료, 로그인 후 정상 완료, 반복 완료, 계정 전환, 네트워크 재시도.
- 새 사건의 재시작이 기존 사건 저장·완료 기록을 지우지 않는지 확인.

### 9.2 저장소 기준

`docs/GAME_QUALITY_GATE.md`의 세 회차를 따른다: ① 핵심 플레이 ② 실패 복구 ③ 회귀·운영. P0/P1 장애가 남으면 수정과 관련 회귀 전 배포하지 않는다. 관련 없는 기능 확장·리팩터링을 품질 개선 명목으로 섞지 않는다.

화면 범위는 320·390·430·768px, 가로모드, 1366×768·1920×1080 등이다. 실제 브라우저·실기기의 키보드·터치·전체화면은 DOM 테스트나 브라우저 창 크기 변경과 별도다. 현재 재판 게임은 혼자 하는 게임이므로 공통 게이트의 다중 사용자 대전 항목은 해당 없음으로 표시한다.

상태: PASS / FAIL / NOT TESTED / BLOCKED를 구분한다. 실제 실행하지 않은 항목은 PASS로 세지 않는다. 테스트 결과에는 환경·시나리오·기대·실제·문제·수정·회귀를 기록한다.

### 9.3 이 인수인계의 근거로 실제 수행한 검증

| 검증 | 결과·한계 |
|---|---|
| v188·v189·v190의 1편 소스 비교 | 1편 디렉터리 동일 확인 |
| 배포 상태 확인 | v189 성공 기록, v190은 확인 당시 미배포 |
| `trial-narrative-dom` + `trial-member-rewards` | jsdom 환경 16개 PASS, 실패 0, 건너뜀 0 |
| 커스텀 진행 검사 | 본편 발언·최소 클릭 수·엔딩 경로·판결문 길이 검사 한계·질문 응답 방식 확인 |
| 이미지 | 원본 주요 자산 시각 확인 |
| 2편 | 현재 소스·기존 인수인계 비교. 이번 문서 작업에서 2편 전체 테스트를 새로 실행한 것은 아님 |
| 실브라우저·실기기·운영 로그인 | 이번 조사에서 NOT TESTED |
| 수정·배포 | 없음. 인수인계 문서만 작성 |

이 결과는 **기준판 조사 결과**다. 새 사건이나 수정된 2편에 그대로 PASS를 상속하지 않는다. 과거 2편 인수인계의 34/34·20/20 등의 수치도 당시 환경의 기록이며 새 실행 결과로 복사하지 않는다.

AI에게 “전에 했던 대화 기억하지?”라고 시작하지 않는다. 위 자료를 실제 첨부하고, 새 사건인지 2편 수정인지, 사용자의 최신 선택 Q1·Q2가 무엇인지 명시한다. 첨부를 읽을 수 없으면 AI는 읽은 척하지 말고 필요한 파일을 정확히 요청해야 한다.
